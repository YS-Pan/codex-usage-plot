本页从原 README 提取计算定义与边界规则，供修改解析、聚合和图表时查阅。字段与文件清单见输出文件参考；费用规则与来源集中维护在 [API 费用估算](../docs/api-cost.md)。

## 统计口径

每个 `token_count` 事件优先采用 `last_token_usage`，它表示该次模型请求实际报告的 token 数。旧日志缺少该字段时，脚本使用相邻 `total_token_usage` 累计值之差。分叉或迁移日志中 turn ID、时间戳、模型和所有 token 计数都相同的事件会被视为完全重复并去除。

任务归属会沿 `parent_thread_id` 递归回溯至主对话，也兼容旧日志中 `source.subagent.thread_spawn.parent_thread_id` 的记录方式。只含元数据而没有 token 事件的中间会话也参与父子关系解析，关系解析先于日期筛选。主对话的请求数、首末活动时间和用量均包含各级子代理；独立分叉不会仅因 `forked_from_id` 而合并。缺失父日志时归入最后一个可确认的父会话 ID；异常环路按稳定 ID 归组。每条去重后的用量只计一次，总 token 用量不会因归组改变。

06 图的任务标签分两行：项目名与开始日期在上，任务名在下。`project_name` 优先使用所选 Codex 数据目录中 `.codex-global-state.json` 保存的主对话项目归属与项目名；未记录归属时，按主会话目录匹配最长项目根目录，匹配失败则使用目录名，明确无项目或无目录时显示 `No project`。子代理目录不覆盖主会话的项目。`thread_started_at` 优先使用主会话 `session_meta` 的创建时间（包括无 token 的主会话），缺失时使用日期筛选前归属到该任务的最早本地用量时间；按所选时区显示日期，不随日期筛选窗口改变。项目名在每次扫描时刷新，增量缓存保留会话开始元数据；`first_seen` / `last_seen` 仍表示所选时段的实际用量活动范围。

缓存输入是输入 token 的子集，推理输出是输出 token 的子集。构成图会将这些重叠字段拆成互斥部分，因此各区域之和等于 `total_tokens`。

这里得到的是当前机器仍保留的本地日志统计，不是 `/usage` 图表的服务器端账户总量。其他设备、云端任务、已清理日志或服务端独有活动可能不在其中。

## 缓存未命中率

未命中率按输入 token 的数量计算，不是未命中缓存的请求数占比：

```text
缓存未命中率 = 100% − 缓存命中率
             = (input_tokens − cached_input_tokens) / input_tokens × 100%
```

图中蓝线为每日未命中率，绿线为最近 7 个日历日按输入 token 加权的未命中率，橙色虚线为整个所选时段的相同比率。先分别汇总输入和缓存输入，再计算比例，避免小请求或低用量日期对平均值产生过大影响。缓存写入计入未命中部分，输出 token 不计入分母。纵轴从 0 开始，按实际数据范围缩放，便于观察高命中率情况下的波动。

无输入 token 的日期没有每日未命中率：CSV 留空，蓝线断开，不记为 0%。7 日窗口内只要有输入 token，仍可计算该窗口的加权未命中率；整个窗口无输入时也留空。整个所选时段都无输入时，图表显示无数据提示。

`daily_usage.csv` 的 `cache_miss_percent`、`rolling_7d_cache_miss_percent` 分别保存每日和最近 7 日未命中率，单位为 0–100 的百分比；`summary.json` 的 `cache_miss_percent` 保存整体未命中率，无输入时为 `null`。

## 动画快照

动画使用当前仍保留的记录按本地日期重放。默认第一帧为今天减 30 个日历日，最后一帧为今天，共 31 帧；即使最近没有日志也推进到今天。显式指定动画结束日期时以该日期为终点，最晚到今天；`report --end` 在没有单独指定动画结束日期时也作为动画终点。演示固定使用合成数据的结束日期。

每帧只使用下一本地午夜之前的 token 事件，今日截到生成开始时刻；跨午夜或跨越当前帧截止时刻的运行区间先截断，再调用原有聚合逻辑。日期推进遵循本地日历，夏令时切换仍按实际秒数计算。空闲日保留，零输入的缓存未命中率继续为缺失值。12、13 图的七日窗口随每帧日期移动。

动画起始日期控制第一帧的时间，不重置累计值；所选统计范围内、第一帧之前的记录也参与累计和 7 日计算。`report --start / --end` 仍决定可用数据范围；独立 `animate` 只能使用结果目录中已有的记录。

整个动画的模型颜色预先从完整所选事件表计算一次，沿用对应静态图片的颜色；每帧复用该映射，不因新模型出现、某模型暂时无用量、用量排名变化或模型数跨过调色板阈值而重新配色。01、02、06、12、13 使用全范围首次出现顺序，auto-review 保持在最上层；其他分类颜色也预先固定。02 的横轴、纵轴范围在动画内固定，累计值按快照更新。

动画复用现有统计与记录单价，09、13 仍是费用估算。MP4 每帧代表一个日历日，默认 4 帧/秒；动画帧率只改变播放速度，不改变统计值。输出格式、条目字段和按需生成入口见 [输出文件参考](../docs/reference.md) 与 [使用指南](../docs/usage.md#动画)。

## 每日运行时间与占比

图中两侧坐标轴都以小时为单位：左轴蓝色柱为合并所有重叠区间后的运行时长，深蓝线为其 7 日均值；右轴橙色曲线为各 session 的运行时长直接相加，并行运行的重叠部分分别累加，所以一天的总量可以超过 24 小时。

左右轴使用相同的范围和映射，相同小时数位于同一高度。数据超过 24 小时时，采用连续的分段线性坐标：0–24 小时占绘图区高度的约 52%，每 4 小时一格；24 小时以上占余下的约 48%，按峰值自动设置较大的小时刻度间隔并压缩显示。分界位于中间附近，用虚线和上半区浅色背景标明，峰值保留日期与实际小时数。两段内部各自线性，跨分界的折线保留准确交点，所有时长都完整显示。数据未超过 24 小时时，使用普通的 0–24 小时线性坐标。

在 `Asia/Shanghai` 时区，每天的计算公式为：

```text
运行占比 = 当天至少有一个 session 正在运行的秒数 / 86400 × 100%
```

按回合的 `task_started` 到 `task_complete` 或 `turn_aborted` 计算运行区间。优先使用日志中的开始时间和 `duration_ms`，缺失时采用开始/结束标记的时间戳；仅有结束记录时，也可由结束时间和持续时长恢复区间。回合内的工具执行和等待包含在运行时间内，两个回合之间等待下一条指令的空闲时间不计入。

所有来源的 session（包括子代理、auto-review 和归档日志）一起计算。例如 A 在 10:00–12:00 运行，B 在 11:00–13:00 运行：左轴合并后为 10:00–13:00，共 3 小时，占全天 12.5%；右轴直接相加为 2 + 2 = 4 小时。分叉或迁移形成的重复日志副本在两种统计中都只计一次。

跨午夜的区间按指定时区拆分到各天。所选范围内没有记录到运行的日期保留为 0，没有 token 的回合也会计入。`--start` 和 `--end` 包含首尾日期。CSV 中保留的今日占比仍除以完整 24 小时，图中用斜线标记尚未结束的日期；CSV 的 `is_complete_day` 为 `False`。

缺少结束标记的回合只计算到该回合最后一条活动日志，不会自动延长到图片生成时间，以免把历史异常中断算成持续运行。这部分是保守估计，正在执行但尚未写出新日志的时间可能被低估；`running_intervals.csv` 中标记为 `incomplete`。无法由时间元数据重建的活动不按 token 密度推测。

`daily_running_time.csv` 的主要字段：

- `running_seconds`、`running_hours`：合并重叠区间后的运行时长；
- `summed_running_seconds`、`summed_running_hours`：各 session 的运行时长直接相加，保留并行区间的重叠时长；
- `running_fraction`：0–1 的比例；`running_percent`：0–100 的百分比；
- `day_seconds`：完整本地日的秒数，中国时区固定为 86400；夏令时切换日按实际的 23 或 25 小时计算，保持比例在 0–100%；
- `rolling_7d_running_percent`：包含空闲日期的 7 日平均占比；
- `rolling_7d_running_hours`：包含空闲日期的 7 日平均合并时长，用于左轴均线；
- `is_complete_day`：生成图片时该日期是否已经结束。

重新运行原命令即可更新这些统计：

```powershell
python -m codex_usage report --timezone Asia/Shanghai
```
