# 目录与运行行为整改

2026 年 11 月 15 日完成运行目录调整，确立了独立安装后的路径规则、可复制的 Windows 启动器及展示媒体的位置。

## 运行目录

- 普通 CLI 默认把报告写到调用目录下的 `codex_usage_report/`，缓存使用平台用户缓存目录。覆盖规则见[安装指南](../../../docs/installation.md#4-状态目录与旧版迁移)。
- Windows 启动器的唯一维护源在项目根。复制到运行目录后，它使用同目录的设置、`cache/` 和 `reports/`。路径覆盖仅在该启动器进程及其子进程生效。
- 迁移已有 SQLite 缓存时使用一致性备份，并用检查点、事件与区间的等价性确认可继续增量更新。独立安装验证使用合成日志，在源码之外检查 CLI、两份启动器的目录隔离，以及 GUI 取消后重试。

## 展示媒体

四件 README 展示媒体从 `codex_usage_report/` 纯路径迁移到 `docs/assets/`。迁移时逐件核对，与实施前 Git blob 相同。后续提交仍按[贡献说明](../../../CONTRIBUTING.md#提交内容)保护两张展示图片。

## 缓存研究

压缩候选通过了数据恢复等价检查。级联删除未达到性能门槛，因此当时沿用 v3 的 SQLite 表结构和设置。后续研究从删除的事务提交阶段继续，并重新核对读取、增量、追加、重建、删除、归档和报告等代表负载。

[候选源码和合成回归](research/cache-v4/README.md)可直接在项目中复查。需要查阅本机部署、归档路径或历史实测时，可查看本地 `private/README.md`（如存在）。
